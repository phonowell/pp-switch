# Pure Provider Switch (pp-switch) ユーザーガイド

[English](user-guide.md) · [简体中文](user-guide-zh.md) · 日本語

pp-switch はプロバイダーを保存し、**Base URL と API キー**を切り替えます。0.0.6 プレビューでは明示した任意のモデルも同期できます。
0.0.6 は限定したネイティブ／API 経路変更にも対応します。アカウント管理やプロトコル変換はしません。既存のモデル・プロトコルと互換性のあるサービスを使用してください。[ダウンロード](https://github.com/phonowell/pp-switch/releases)。

## 最初の切り替え

1. クライアントを初期化。0.0.6 は下記のネイティブアカウント経路にも対応。
2. pp-switch を開き、上部のタブでクライアントを選択。
3. 「追加」で名前、HTTP(S) URL、空でないキーを入力し、任意のモデルを確認して保存。
4. 各行の鉛筆の右にある切り替えアイコンを押す。設定を再読込しないクライアントは再起動。

保存はアプリ内の一覧のみを変更します。青い「使用中」はクライアントの**URL・キー・指定したモデル設定**が保存済みの接続と一致する印です。状態は記憶した ID ではなくクライアントのファイルから読み取ります。各行の鉛筆ボタンで編集し、キャンセルで下書きを破棄します。保存だけでは適用されません。一致する項目の切り替えボタンは無効です。削除は保存済み項目のみで、クライアントの設定は戻しません。
同じクライアントの名前は一意です（前後の空白・大文字小文字を無視）。インポート時は最初の空き番号で `名前 (2)` のように区別します。
同じ接続は別名で保存できます。既存の同名項目は保持します。URL・キー・指定したモデル設定が一致するすべての項目に「使用中」を表示し、各項目を個別に編集できます。
行の独立した選択状態はありません。下部の状態・切り替え領域とすべてのツールチップを削除しました。
タブ右側の小さな歯車で同じウィンドウ内の設定へ進み、「戻る」で一覧へ戻ります。
画面と開いているダイアログはシステムのライト／ダーク設定に追従し、外観の切り替えで下書きや選択を失いません。

**「使用中」は対応するユーザー設定ファイルだけを確認します。** 実行中のセッションは検証せず、テストリクエストも送りません。新しいプロバイダーは維持されたモデルに対応する必要があります。Claude 起動時の未知モデルカタログ警告だけでは切り替え失敗とは判断できません。実際のリクエストエラーと起動時のモデル表示を区別してください。

## 任意のモデル（0.0.6 プレビュー）

Claude もモデルは任意です。保存済みのモデルなし項目は URL／キーを直接切り替え、一致すれば「使用中」と表示します。
既存項目とインポートでは明示したモデルを優先します。Claude の既定値がない場合、指定済みの Sonnet、Opus、Haiku 割り当てを順に使用します。
それ以外は五つのクライアントとも URL とキーが完全に一致する場合のみ、対応するローカル設定からモデルを事前入力します。Claude の別名は既存の割り当てで解決し、他の接続のモデルを引き継ぎません。

Claude の追加・編集・インポートで具体的なモデルがない場合、編集可能な `claude-sonnet-5` を実際に入力します。
これは製品の候補であり、すべてのプロバイダーでの互換性は保証しません。対応を確認するか変更してください。空欄にするとクライアントのモデルを維持します。
事前入力は未保存の下書きです。保存してから切り替えを押してください。他のクライアントの新規モデル欄は空欄です。DSH のネイティブアカウントから API への移行は `deepseek-flash` を既定にします。

Claude はルート `model`、`env.ANTHROPIC_MODEL` と Haiku／Sonnet／Opus を同期し、割り当てを展開して個別に上書きできます。
既存 `ANTHROPIC_SMALL_FAST_MODEL` は Haiku に従います。Codex はルート `config.toml.model`、
Gemini は `.env.GEMINI_MODEL` と `settings.json.model.name` を復旧可能な書き込みで同期します。
Grok は選択したカスタム profile のモデルを変更し、ネイティブから PPS profile を作る際は明示した既定モデルが必要です。
DSH は共通 `agent-default-model` のモデルを変更します。保存値を消すと管理を止めますが、クライアントの値を削除・復元しません。
モデルカタログ、互換性やコンテキスト情報は推測しないため、未知モデル警告が残る場合があります。
旧モデルなし項目も直接切り替えできます。0.0.4 配布版には含まれません。

## クライアントの前提と書き込み対象

| クライアント | ユーザー設定の場所 | 管理する値 |
| --- | --- | --- |
| Claude Code | `~/.claude/settings.json` | `env.ANTHROPIC_BASE_URL` と既存 `env.ANTHROPIC_AUTH_TOKEN` または `env.ANTHROPIC_API_KEY` |
| Codex | `~/.codex/config.toml` と必要に応じて `~/.codex/auth.json` | 選択中のカスタムプロバイダーの `base_url`、既存 `experimental_bearer_token` または `OPENAI_API_KEY` |
| Gemini CLI | `~/.gemini/.env` | `GOOGLE_GEMINI_BASE_URL` と `GEMINI_API_KEY` |
| Grok Build | `~/.grok/config.toml` | 選択済みカスタム profile の `base_url` とインライン `api_key` |
| DeepSeek Harness CLI／Web | `$DSH_HOME/cordis.patch.yml` と `.credentials.yaml`（既定 `~/.dsh`） | 共有ルートの `baseURL` と既存 `refs.<apiKeyEnv>` |

`~` は各 OS のユーザーホーム。Claude は `CLAUDE_CONFIG_DIR`、Codex は `CODEX_HOME` に対応。DSH は `DSH_HOME` に対応。Gemini 設定は限定した認証選択と明示モデルも含みます。

**Claude：** キーフィールドが両方なければ `ANTHROPIC_AUTH_TOKEN` を使用します。両方存在する場合、`apiKeyHelper`、有効な Bedrock / Vertex / Foundry モードは拒否します。OAuth ログインの管理やクラウド認証の変換はしません。

**Codex：** 対応カスタム経路は選択とプロトコルを維持します。Bearer 経路は OpenAI 認証を要求できず、
ファイルキー経路は既存 API キー認証、活動中 OAuth なし、外部／keyring キー保存なしが必要です。
ネイティブログインからは予約 `pps` Responses／bearer テーブルを選択し、OAuth 資格情報と保存方式は維持します。
PPS 以外の同名テーブル、活動中 profile、強制ログイン設定は移行を拒否します。`env_key` など外部キーは非対応です。

**Gemini：** 未指定／ネイティブ、`oauth-personal`、`gemini-api-key` に対応。プロバイダーへ切り替えると
`security.auth.selectedType` を `gemini-api-key` にします。クラウド／Vertex と競合する別キー／URL は拒否します。
明示モデルだけが `settings.json.model.name` を変更し、OAuth キャッシュは維持します。

**Grok：** 既存インラインキー profile は選択とプロトコルを維持します。ネイティブからは明示した既定モデルで
専用 `pps` Responses profile を選択します。他の profile と `auth.json` は維持します。

**DSH：** `@deepseek-ai/dsh-base` を含む `headless`／`web` profile を初期設定してください。
ホーム patch は profile patch の後に読み込み、CLI／Web で共有します。対応 API 経路は既存キー参照を維持します。
ネイティブアカウントからは `deepseek-official` と既存参照（既定 `DEEPSEEK_API_KEY`）を選択し、
欠落した version-1 API キーコンテナーだけを作ります。共通上書きのない競合経路と外部資格情報を拒否します。
アカウント記録、manifest、profile patch、継承カタログ全体を維持します。HMR 無効時は再起動してください。
起動 patch・独自 bundle・別プロセス環境が優先される場合があります。

## 公式復元（0.0.6 プレビュー）

五つのクライアントの先頭には切り替えのみの固定「公式」行があります。ネイティブ経路に戻し、履歴ファイルの復元はしません。
ログイン・ネットワーク要求は行いません。必要ならクライアントで再ログイン・再起動してください。

- Claude は API URL／キー／token、五つの管理モデル環境項目、ルートモデルを削除します。資格情報、hooks、権限、モデルカタログ、既存 proxy／コンテキストは維持し、外部 helper／クラウドは拒否します。
- Codex はルートのプロバイダー／モデル、API 専用強制ログイン、`auth.json.OPENAI_API_KEY`／API 認証方式を削除し、OAuth token と非活動テーブルは維持します。
- Gemini は管理 URL／キー／モデル環境項目を消し、`oauth-personal` を選び、`model.name` を削除します。OAuth キャッシュと他の設定は維持します。
- Grok は既定選択と同じ profile を参照する要約選択を消し、非活動 profile とネイティブ資格情報は維持します。
- DSH は `deepseek-account`／`deepseek-flash` を選び、共通の完全な上書きでアカウントアダプターの独自 URL を消します。API／アカウント資格情報、モデルカタログ、両 profile patch は維持します。

「公式」はファイルのネイティブ経路／認証だけを確認し、ログイン済みとは保証しません。非対応設定は書き込み前に拒否します。
複数ファイルはプロバイダー切り替えと同じ復旧可能なトランザクションを使います。

ユーザー設定のみが対象です。プロジェクト設定、起動引数、クライアント環境変数が優先される場合があります。pp-switch が見える環境の上書きは通知しますが、別ターミナルは異なる可能性があります。起動環境の解決はユーザー側で行ってください。シェル設定やシステム環境変数は変更しません。

## プロバイダーの追加

名前、URL、キーを手動で入力します。0.0.6 プレビューではブラウザーから
`ccswitch://v1/import` / `ppswitch://v1/import` の Provider リンクを開き、
未保存のプレビューを表示します。名前、URL、マスクされたキー、任意のモデルを確認して保存します。
保存はクライアントに適用しません。リモート設定や他の設定は取り込みません。
既存の下書きは保持され、完了・キャンセル後にリンクを再度開く必要があります。
「設定 → インポートリンクを登録」は未使用のスキームのみを登録し、既存のハンドラーを保持します。
起動時に登録しません。0.0.4 配布版は非対応です。保存済み項目は保持します。

sub2api の Claude リンクには現在モデルがありません。対応する Claude 設定に同じ URL とキーがあればモデルを事前入力します。それ以外は `claude-sonnet-5` を候補にし、変更や消去が可能です。保存だけではクライアントファイルを変更しません。
Claude の割り当てだけのリンクは Sonnet、Opus、Haiku の順に既定モデルとして表示します。明示された既定値が優先です。使用量スクリプトは破棄し、実行しません。

## 言語とデータ保存

Linux は Noto Sans CJK（Debian/Ubuntu: `sudo apt install fonts-noto-cjk`）または WenQuanYi Zen Hei をインストールしてください。Xft は欠落した字形を自動補完しないため、CJK を含むシステムフォントが必要です。フォントファイルは同梱しません。

英語・簡体字中国語・繁体字中国語・日本語に対応。初回はシステム言語、非対応なら英語。「設定 → 言語」でラベル・ダイアログ・状態を即時変更し、下書きと選択を保持します。

| OS | データディレクトリ |
| --- | --- |
| macOS | `~/Library/Application Support/pp-switch` |
| Windows | `%LOCALAPPDATA%\pp-switch` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/pp-switch` |

`providers.json` は接続とキー、`ui.json` は言語のみ。Unix 0600 / Windows 現在ユーザー ACL でアクセスを制限します。**マスク表示は暗号化ではありません。** ロック・復旧ファイルで書き込みを調整し、不正データは通知して勝手に置換しません。バックアップは非公開で保管し、診断へ貼り付けないでください。

## 手動更新

macOS 0.0.2 は新しいアイコン資源を拒否するため、今回だけ手動ダウンロードが必要です。0.0.3 以降の更新対象にはアイコンを含めます。

1. 「設定 → 更新を確認」を押す。起動時や定期的な確認はありません。
2. 新しい対応版があればバージョンと確認画面の「リリースノート」を読んで「インストールして再起動」。キャンセルで変更なし。プレビュー版は新しいプレビューも取得します。先に保存してください。未保存の編集は再起動で失われます。
3. 本リポジトリの OS / CPU 対応 GitHub パッケージのみを取得し、GitHub の SHA-256 摘要で検証。一時助手がアプリ終了を待ち、バックアップ付きでインストールして再起動します。

成功した確認結果はアプリ実行中の 5 分間保存され、インストールをキャンセルしても残ります。
再度押すと GitHub メタデータを再取得せず結果を再利用します。失敗時はすぐ再試行できます。
GitHub のリクエスト制限や許可外のリダイレクト先は専用メッセージで通知します。
タイムアウトやメタデータの不完全な取得は失敗として通知し、更新ボタンを再び有効にします。

更新はプロバイダー / キー情報を送信せず、アプリ所有ファイルだけを置き換えます。失敗時は旧ファイルを復元し、外部編集と競合すればバックアップを保持して通知します。

単独のバイナリでなく、展開した完全なパッケージから起動してください。設置先は書き込み可能である必要があります。他の pp-switch ウィンドウを閉じ、更新中にアプリのファイルを編集しないでください。読み取り専用なら書き込み可能な場所へ移動、または手動置換。接続エラー / レート制限は後で手動再試行。再起動失敗時は自分で開き直してください。未署名パッケージの GitHub 摘要は転送の完全性を確認し、独立した発行者署名ではありません。macOS は Apple Developer 署名・公証なしです。

## トラブル対処

| 状況 | 対処 |
| --- | --- |
| 非対応・不完全な設定 | 上記の前提を確認し、クライアント自体で初期設定してください。拒否した設定は変更しません。 |
| 古いプロバイダーが使われる | クライアントを再起動し、プロジェクト設定・起動引数・環境変数を確認してください。 |
| ファイル変更・シンボリックリンク拒否 | 再試行前に宛先を確認。リンクや外部変更は上書きしません。 |
| GitHub 接続失敗 / HTTP 403 | 後で手動再試行。出口の匿名 API 枠を使い切った可能性があります。アプリは GitHub ログインを要求しません。 |
| 更新・再起動失敗 | 通知されたバックアップを保管し、完全なパッケージと書き込み権限を確認。開き直すか手動ダウンロードしてください。 |
| Linux で CJK の字形が欠ける | 上記の CJK フォントをインストールしてください。 |

Codex 複数ファイルの変更は復旧可能ですが、全体が原子的ではありません。
次の使用時に復旧を試み、競合時はジャーナルを保持して外部変更を守ります。
主画面を閉じるか macOS の「終了」を選ぶと、ダイアログを含めて終了し、常駐助手はありません。
現在の性能と制限は[検証記録](verification.md)、予算は [SPEC PP-11](../SPEC.md#acceptance-contract) を参照してください。
